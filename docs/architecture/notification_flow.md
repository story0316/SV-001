## 1. 위험도 계산 알고리즘

### 위험도 점수 (0-100)

```
Risk Score = 
  min(100,
    (Days_No_Response × 10) +          // 무응답 일수 (최대 50점)
    (Pattern_Deviation × 25) +         // 응답 패턴 변화 (최대 25점)
    (Cognition_Errors × 20) +          // 인지 체크 오류 (최대 20점)
    (Previous_Risk × 15) +             // 과거 위험 이력 (최대 15점)
    Seasonal_Factor                    // 계절 요인 (최대 5점)
  )
```

### 위험 수준 분류

```
🔴 Critical (80-100):  즉시 조치 필요 (24h 내)
🟠 High (60-79):       오늘 중 연락 필요
🟡 Medium (40-59):     이번주 중 확인
🟢 Safe (<40):         정상 관찰
```

## 3. 대상자별 알림 정책

### 복지사

```
위험도 80+ (Critical):
  - 즉시 PUSH 알림
  - 이메일 (백업)
  - 1시간 안 조치 없으면 재알림

위험도 60-79 (High):
  - PUSH 알림
  - 조치 기한: 당일 18:00

위험도 40-59 (Medium):
  - 대시보드 배지만 (알림 안 함)

위험도 <40 (Safe):
  - 알림 없음
```

### 보호자

```
조건:
  1. 24h 이상 무응답
  2. 이전 24h 내 알림 없음
  3. 보호자가 과도한 알림 선호 설정 없음

메시지:
  "어머니 김순자님의 응답이 없어요.
   담당 복지사 이민지님도 확인 중입니다.
   필요하면 [전화하기]를 눌러주세요."

채널:
  - 우선: PUSH + KakaoTalk
  - 부차: 이메일 (설정에 따라)
```

### 관리자

```
일일 요약 보고서 (09:00 발송):
  - 어제 위험 탐지 건수
  - 조치 완료율
  - 미조치 대상 수

주간 리포트 (월 09:00 발송):
  - 위험도 추이
  - 응답률 변화
  - 효율성 지표
```

## 4. 보호자 알림 자동 생성 로직

### Trigger: 무응답 24h + 위험도 상승

```
Step 1: 조건 확인
┌─────────────────────┐
│ 무응답 24h 이상?   │ → NO → 종료
│ 위험도 50점 이상?   │
└────────┬────────────┘
         │YES
         ▼
Step 2: 과거 알림 확인
┌──────────────────────────────┐
│ 지난 24h 내 보호자          │
│ 알림 발송한 기록?          │ → YES → 재알림 안 함
└────────┬─────────────────────┘
         │NO
         ▼
Step 3: 알림 초안 자동 생성
┌────────────────────────────────┐
│ "어머니 {{name}}님의 응답이   │
│  없어요. 담당 복지사          │
│  {{worker_name}}님도 확인 중   │
│  입니다."                     │
└────────┬─────────────────────┘
         │
Step 4: 복지사 검토 대기
┌────────────────────────────────┐
│ 복지사 "보내기" 또는 "수정"   │ → 수정 시 초안 무시
│ 클릭 대기                     │
└────────┬─────────────────────┘
         │
Step 5: 발송 및 기록
├─→ notifications 테이블 저장
├─→ KakaoTalk + PUSH 동시 발송
└─→ Realtime 업데이트
```

## 5. 오류 방지 메커니즘

### False Positive 최소화

```
Rule 1: 응답 지연 vs 무응답 구분
  - 응답하지만 늦은 경우 → 위험도 낮춤
  - 3일 연속 응답 안 함 → 위험도 올림

Rule 2: 특수 상황 예외 처리
  - 보호자가 "여행중" 표시 → 알림 미발송
  - 담당자가 "대기중" 상태 → 재알림 금지

Rule 3: 연령대별 조정
  - 80세 이상 → 위험도 기준 낮춤 (더 신중)
  - 독거 + 건강 정보 있으면 → 기준 높임
```

### 알림 피로 방지

```
Daily Cap:
  - 복지사 1명당 최대 5건 Push 알림/일
  - 초과 시 이메일로 변경

Quiet Hours:
  - 21:00 ~ 09:00 Push 금지
  - 업무 외 시간 존중

Repetition Control:
  - 같은 클라이언트 반복 알림 (최대 2회/일)
  - 조치 없으면 다음날까지 재알림 금지
```

## 6. 채널별 전송 방식

### PUSH (Firebase Cloud Messaging)

```
즉시 알림 필요시:
  - 위험도 80+ (복지사)
  - 무응답 24h+ (보호자)

특징:
  - 즉시 배달
  - 사운드 + 진동
  - 앱 미설치 시 동작 안 함
```

### Email (SendGrid)

```
기본 또는 백업 용도:
  - Push 미수신 확인용
  - 상세 정보 포함 가능
  - 일일 요약

특징:
  - 지연 가능 (1시간)
  - 상세 정보 포함
  - 100% 배달 추적 가능
```

### SMS (NAVER Sens)

```
긴급 알림만:
  - 응답 없음 + 위험도 매우 높음
  - 보호자 2회 재시도 후

특징:
  - 가장 비쌈
  - 100% 배달
  - 가장 높은 우선순위
```

### KakaoTalk

```
주로:
  - 고령층 응답 알림
  - 감사 메시지
  - 일회성 알림

특징:
  - 고령층 선호
  - 채널 내 메시지 (앱 필요 없음)
```
