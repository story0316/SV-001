## 1. 핵심 명제

> **"이 서비스는 노인이 사용하는 게 아니다. 노인의 일상이 이 서비스를 통해 흐른다."**

기존 복지 서비스의 실패 패턴:
```
사용자에게 행동을 요구한다
  → 새로운 학습 필요
  → 마찰 발생
  → 사용 포기
```

우리의 설계 패턴:
```
일상 흐름에 서비스가 끼어듦
  → 기존 습관 활용 (카카오톡)
  → 최소 응답만 요구
  → 자연스러운 사용
```

---

## 2. 5대 제품 철학

### 1. ZERO FRICTION
- 고령층에게 새로운 행동을 학습시키지 않는다
- 카카오톡 = 이미 알고 있는 인터페이스
- 앱 설치/회원가입 = 절대 금지

### 2. TRUST FIRST
- 관계를 형성하지 않으면 데이터도 의미 없다
- 첫 응답이 가장 중요 (전환율)
- 감정적 안정감 > 정보 정확도

### 3. SILENT GUARD
- 정상 상태는 조용해야 한다
- 위험할 때만 소리 낸다
- 알림 피로 = 절대 금지

### 4. EVIDENCE TRAIL
- 복지사의 모든 행동은 자동 기록된다
- 책임 근거 확보
- 규제/감시 대비

### 5. SCALE BY DEFAULT
- 1개 기관 구조 = 100개 기관도 지원
- B2G 확장성 초기부터 고려
- 테넌트 격리, 권한 역할화

## 3. 서비스 레이어 구조

```
┌─────────────────────────────────────────────────────┐
│  LAYER 3: B2G Dashboard (지자체/기관 통계·보고)     │
│  → 정책 지표, 월간 리포트, 효율성 분석               │
├─────────────────────────────────────────────────────┤
│  LAYER 2: Operations (복지사 업무 흐름 자동화)      │
│  → 위험 우선순위, 빠른 조치, 자동 기록, 보고서 생성  │
├─────────────────────────────────────────────────────┤
│  LAYER 1: Care Interface (보호자 안심 확인)         │
│  → 부모 상태, 무응답 알림, 복지사 연락처            │
├─────────────────────────────────────────────────────┤
│  LAYER 0: KakaoTalk Channel (고령층 일상 접점)      │
│  → 일일 안부, 인지 체크, 친근한 언어                │
└─────────────────────────────────────────────────────┘
```

### LAYER 0: KakaoTalk Channel
**사용자**: 70~85세 고령층
**접점**: 카카오톡 채널
**상호작용**: 버튼 2~3개 탭으로 완료
**데이터**: 응답 여부 (Yes/No) + 응답 시간

### LAYER 1: Care Interface
**사용자**: 40~60세 보호자
**접점**: 모바일 웹
**니즈**: "부모 안전한지만 빠르게 확인"
**정보**: 상태(정상/주의/위험) + 마지막 응답

### LAYER 2: Operations
**사용자**: 복지사/지자체 담당자
**접점**: 웹 대시보드 + 모바일 앱
**니즈**: 위험자 빠른 확인 → 즉시 조치
**정보**: 우선순위 리스트 + 히스토리 + 자동 리포트

### LAYER 3: B2G Dashboard
**사용자**: 기관장/지자체 통계담당자
**접점**: 웹 대시보드
**니즈**: 월간 성과 + 정책 지표 + 예산 효율
**정보**: 지역별 통계, 기관별 비교, 자동 보고서

## 4. 핵심 시장 가설

### 가설 1: 고령층은 새로운 기술을 거부하지 않는다
**거부하는 것**: 복잡성
**해결책**: 버튼 2개만 제시

### 가설 2: 보호자의 불안감은 정보 과부하에서 온다
**현재**: 매일 "엄마 어디야? 뭐 해?"
**우리 솔루션**: "엄마 정상입니다" 1문장

### 가설 3: 복지사 병목은 기술 부족이 아니라 시간 부족
**문제**: 기록에 30분 소비
**솔루션**: 통화 후 30초 기록 + AI 자동 보고서

### 가설 4: 지자체는 "효율성 증명"으로만 움직인다
**증명**: "복지사 업무시간 30% 단축" 수치화
**확장**: 1개 지자체 성공 → 100개로 확대

## 6. 성공 지표 (각 Persona별)

### Persona A: 고령층
```
응답률 ≥ 80%
→ 일주일에 80% 이상 응답 가능
→ 실제 운영 가능 증명

응답 시간 ≤ 5초
→ 버튼 찾아 누르는 시간
→ 인지 부하 최소화 증명

이탈률 < 5%
→ 1개월 이상 사용 지속
→ 신뢰 형성 증명
```

### Persona B: 복지사
```
대상자당 관리 시간 30분 → 15분으로 단축
→ 위험 판단 + 조치 시간 50% 감소

기록 시간 0분 (자동)
→ 현장에서 따로 기록 안 함
→ 통화 후 팝업으로 30초 완료

위험 탐지 정확도 ≥ 85%
→ False Positive < 15%
→ 실제 조치 대상 정확성
```

### Persona C: 보호자
```
알림 수신 후 응답 시간 ≤ 5분
→ 위험 알림 보고 즉시 행동

과도한 알림 < 주 1회
→ "울면 모르는" 알림 피로 방지

안심도 점수 ≥ 8/10
→ 부모 안전하다고 느낌
```

## 7. 경제 모델 (Phase 5 이후)

### 수익화 경로
```
Model 1: 지자체 SaaS (월 구독)
  → 인원당 비용 (예: 노인 1명당 500원/월)
  → 지자체 장애인복지과 예산

Model 2: 기관 라이선스
  → 종로노인복지관 같은 시설 (월 100만원)
  → 자체 케어 관리 효율화

Model 3: 보호자 선택 구독 (초기 Free)
  → 비용 저감형 / 프리미엄
  → 보호자 직접 결제 (장기 목표)
```

### 가격 책정 논리
```
복지사 시간당 비용: 15,000원
→ 복지사 1시간 절감 = 1.5만원
→ 월 10시간 절감 × 1.5만원 = 15만원
→ 대상자 100명 관리 기관 = 월 600만원 절감
→ 월 구독료 100만원 = 매우 저렴한 가격
```

## 8. 위험 요소 & 대응

| 위험 | 영향 | 대응 |
|------|------|------|
| 고령층 기기 미보유 | 가장 취약층 제외 | 복지관 태블릿 배포 지원 |
| 카카오톡 비활성화 | 서비스 불가 | 초기 진입장벽 (선별) |
| 오류 기록 | 책임 문제 | 모든 조치 타임스탬프 자동 저장 |
| 위험도 과탐지 | 복지사 피로 | AI 모델 정확도 ≥ 85% 유지 |
| B2G 정책 변동 | 계약 취소 | 유연한 리포팅 형식 지원 |

## 9. 향후 확장 (Post-MVP)
