## 1. 고령층 UX 원칙 (Persona A 중심)

### 1-1. 텍스트 & 가독성

**필수 규칙**:
```
최소 폰트: 18px (절대 금지 16px 이하)
강조 제목: 24px 이상
고대비:   전경/배경 4.5:1 이상 (WCAG AAA)
폰트:     sans-serif만 (명조체 절대 금지)
줄 높이: 1.6 이상 (글 줄 간격 넓음)
```

**위반 사례**:
- ❌ "자세히 보기" (14px 링크 텍스트)
- ❌ 회색 글씨 + 흰 배경 (명도 차이 < 3:1)
- ✅ "자세히 보기" (20px, 검정색)
- ✅ 진한 파란색 + 흰 배경

### 1-2. 터치 영역

**필수 규칙**:
```
모든 버튼:           최소 44px (iOS HIG)
복지사 주요 CTA:     최소 56px 권장
고령층 주요 CTA:     최소 64px (손떨림 고려)
버튼 간 간격:       최소 8px (오터치 방지)
```

**위반 사례**:
- ❌ 작은 X 버튼 (20px × 20px)
- ❌ 옆 버튼과 2px 간격
- ✅ [닫기] 버튼 (56px × 56px)

### 1-3. 화면 구성

**필수 규칙**:
```
한 화면 = 1개의 주요 행동만 (극도로 단순화)
스크롤 = 절대 금지 (화면에 모든 콘텐츠 표시)
선택지 = 최대 2~3개 (인지 과부하 방지)
입력 필드 = 절대 금지 (버튼만 사용)
설정 화면 = 절대 금지
```

**위반 사례**:
- ❌ 한 화면에 [오늘], [일주일], [월간], [맞춤] 4개 선택지
- ❌ 스크롤하면 추가 콘텐츠 표시
- ✅ [네 했어요] [아직이에요] 버튼 2개만

### 1-4. 색상 사용

**필수 규칙**:
```
색상 = 신호가 아니라 보조 (텍스트 + 아이콘 필수 병행)
위험도: 색상 + 아이콘 + 텍스트 3중 표현
예: "🔴 위험" (아이콘 + 색 + 글자)

색상 이름 = 절대 금지 ("파란색" 말고 "확인")
```

**위반 사례**:
- ❌ 빨간 배경만 (색맹 사용자 = 화면 안 봄)
- ❌ 배경색만 다름 (명도 차이 없음)
- ✅ 🔴 + 빨강 + "위험" 텍스트

### 1-5. 피드백 & 상태 표시

**필수 규칙**:
```
모든 행동 후 = 명확한 피드백 (음성/시각 동시)
진행 상태 = 명시적 표시 (1/3 단계 등)
오류 = 문제 설명 + 해결 방법 (기술 용어 금지)
확인 필요 = 되돌리기 기회 제공
```

**위반 사례**:
- ❌ 버튼 누르고 아무 반응 없음
- ❌ "에러" 메시지만 (뭐가 잘못됐는지 모름)
- ✅ "✅ 저장되었습니다" + 0.5초 후 자동 닫힘
- ✅ "번호가 틀렸어요. 다시 확인해주세요"

## 2. 복지사 운영 효율 원칙 (Persona B 중심)

### 2-1. 정보 아키텍처

**최적화**:
```
위험도 = 항상 먼저 (🔴 > 🟠 > 🟡 > 🟢 순)
이름/나이 = 두 번째 (누구인가)
위험 이유 = 세 번째 (왜 위험한가, 1줄)
행동 버튼 = 가장 큰 터치 영역 (전화/기록/알림)
```

**위반 사례**:
- ❌ 가나다순 정렬 (위험도 무시)
- ❌ 위험도 = 작은 숫자 (87/100)
- ✅ 위험도 = 대형 바 (████████░░)

### 2-2. 클릭 최소화

**규칙**:
```
위험자 전화 = 탭 2회 이하
기록 저장 = 탭 5회 이하 (30초)
보고서 생성 = 0회 (자동)
```

**달성 방법**:
- 기본값 제공 (AI가 제안한 값)
- 다음 연락 일정 자동 설정
- 보호자 알림 초안 자동 생성

### 2-3. 의사결정 지원

**규칙**:
```
선택지 3개 이상 = 절대 금지
기본값 = 매우 신중히 결정 (80% 유스케이스 커버)
수정 가능 = 기본값 제공하되 변경 쉽게
```

**예시**:
```
[다음 연락 일정]
Default: "내일 오전" (기본값)
또는: [오후] [3일 후] [1주일 후] [날짜 직접]
```

### 2-4. 기록 자동화

**규칙**:
```
모든 조치 = 자동 타임스탐프 저장
통화 내용 = 팝업 모달 (통화 직후 나타남)
음성 입력 = 선택사항 (현장용)
```

## 3. 보호자 안심 원칙 (Persona C 중심)

### 3-1. 정보 최소화

**규칙**:
```
표시: "정상" vs "확인 필요"만
숨김: 복잡한 수치, 건강 데이터, 위험 스코어
목표: "엄마 괜찮다"는 느낌
```

**위반 사례**:
- ❌ "위험도 78/100, 인지 체크 오류율 60%"
- ✅ "✅ 오늘 정상입니다"

### 3-2. 알림 제어

**규칙**:
```
정상 상태 = 절대 알림 금지
무응답 24h 초과 = 1회만 (반복 금지)
보호자 선택 알림 = 가능 (매일/주 1회)
```

### 3-3. 신뢰 형성

**규칙**:
```
담당 복지사 정보 = 항상 표시
응답 히스토리 = 최근 7일 도트 패턴 (과거 신뢰도)
담당자 연락처 = 바로 호출 가능
```

## 4. 절대 금지 사항 (DO NOT)

### 4-1. 고령층 절대 금지
```
❌ 복잡한 메뉴 구조
❌ 햄버거 메뉴 (≡ 아이콘)
❌ 작은 아이콘 (13px 미만)
❌ 긴 문장 (20자 이상)
❌ 기술 용어 ("API", "서버", "동기화")
❌ 미안해하는 톤 ("죄송합니다", "오류 발생")
❌ 설정 화면
❌ 앱 설치 요구
❌ 복잡한 가입 프로세스
```

### 4-2. 복지사 절대 금지
```
❌ 일일 활동 수동 기입
❌ 판단 관련 선택지 3개 이상
❌ 기록을 위한 추가 앱
❌ 실시간 위치 추적
❌ 과도한 알림 (하루 10개 이상)
```

### 4-3. 보호자 절대 금지
```
❌ 부모의 위치 정보 노출
❌ 매일 알림
❌ 복잡한 분석 그래프
❌ 앱 설치 강제
```

## 5. 아이콘 & 이모지 가이드

**고령층 친화 이모지**:
```
😊 = 긍정적 감정
😢 = 주의 필요
❌ = 위험/문제
✅ = 완료/확인
🔴 = 즉시 조치
🟠 = 주의
🟡 = 확인 필요
🟢 = 정상
📞 = 전화
📝 = 기록
```

**금지 이모지**:
```
❌ 손 모양 👆 (너무 작음)
❌ 화살표 (방향 혼동)
❌ 숫자/기호 (의미 불명확)
```

## 6. 반응형 설계

### 화면 크기별 최적화
```
모바일 (280~480px): 기본 타겟
  - 세로 방향만
  - 터치 최적화
  - 스크롤 금지

태블릿 (768~1024px): 보조
  - 가로 모드 지원
  - 멀티 패널 가능

데스크톱 (1200px+): 나중
  - 아직 불필요
```

## 7. 접근성 체크리스트

### WCAG 2.1 AA 준수
- [ ] 색상 대비 4.5:1 이상 (일반)
- [ ] 색상 대비 3:1 이상 (대형)
- [ ] 터치 영역 44px 이상
- [ ] 키보드 네비게이션 가능
- [ ] 화면 낭독기 호환 (aria-label)
- [ ] 1시간 연속 사용 시 피로도 낮음

### 실제 테스트
- [ ] 74세 사용자 (손 떨림) 테스트
- [ ] 복지사 현장 테스트 (30분)
- [ ] 보호자 모바일 웹 테스트
- [ ] 접근성 도구 자동 검사 (axe)

## 8. 설계 의사결정 플로우

### 새 기능 추가 시 확인
```
1. 이것이 꼭 필요한가?
   → No → 제거
   → Yes → 2번

2. 이것을 더 단순하게 할 수 있나?
   → Yes → 단순화하고 2번 반복
   → No → 3번

3. 고령층이 이해할 수 있나?
   → No → 다시 설계
   → Yes → 4번

4. 복지사가 3초 내 판단할 수 있나?
   → No → 정렬/강조 수정
   → Yes → 구현

5. 보호자가 과도하게 불안해할까?
   → Yes → 알림 끄기
   → No → 완료
```
